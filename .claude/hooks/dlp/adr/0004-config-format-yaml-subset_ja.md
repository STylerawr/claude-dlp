# 0004: 設定ファイルを JSON から、自前の YAML サブセットに変更する

[← ADR一覧に戻る](List-Of-ADR_ja.md)

## ステータス

Accepted

## 背景

[0002](0002-replace-betterleaks_ja.md) で `dlp-masker.py` にハードコードされていた設定
（`TARGET_DIRS` など）を外部ファイルへ切り出す際、まず `dlp.config.json` を採用した。
しかし JSON にはコメント構文が無く、各項目の説明を書けない。応急処置として、実際の設定値とは
別に `_comment` という同階層のオブジェクトへ項目ごとの説明をまとめる形にしたが、これは
「わかりにくい」というフィードバックを受けた。

## 検討した選択肢

1. **TOML**: 配列・ネストを JSON とほぼ同じ感覚で書け、項目ごとに `#` コメントを自然に付けられる。
   ただし標準ライブラリの `tomllib` で読むには Python 3.11 以降が必要で、hook の動作要件
   （それまで「Python 3.9 以降」としていた）を引き上げる必要がある。
2. **INI（`configparser`）**: 標準ライブラリだけで Python 3.9 以降のまま変更不要。ただし
   `target_dirs` のような配列はカンマ区切り文字列になり、TOML ほど自然には書けない。
3. **YAML（PyYAML 使用）**: もっとも見慣れた記法。しかし標準ライブラリに YAML パーサは無く、
   本格的な YAML を読むには PyYAML を追加依存として導入する必要がある。これは
   [0002](0002-replace-betterleaks_ja.md) で betterleaks をやめた理由（別ツールのインストールが
   必要）と同じ問題を再び持ち込むことになる。
4. **YAML（自前の最小サブセットパーサ）**: PyYAML を使わず、この設定ファイルに必要な形
   （コメント・フラットな `key: value`・文字列の配列）だけを読む専用パーサを自分で書く。
   標準ライブラリのみで完結し、Python バージョン要件も変わらない。

ユーザーには 2 段階で選択してもらった。まず形式そのものを 1〜3（+YAML 全般）から選んでもらい
YAML を選択。続けて、YAML の読み込み方法を「PyYAML を追加依存として導入する」か
「自前の最小パーサを書く」かで選んでもらった。

## 決定

選択肢 4（自前の最小 YAML サブセットパーサ）を採用した。

理由は明確に「betterleaks を廃止した理由をもう一度持ち込みたくない」という点にあった。この
設定ファイルの形は固定（フラットな `key: value` と文字列のリストだけ）で複雑な YAML 機能を
必要としないため、フルスペックの YAML パーサへの依存を正当化できるほどの複雑さが無い。

## 結果

- `dlp.config.yaml` + `yaml_lite.py`（100 行未満）が設定の実体になった。
  `dlp-masker.py` と `dlp_scanner.py` の両方から import される。
- `yaml_lite.py` が対応するのは次だけ: 行頭コメントおよび引用符の外側の ` #` 以降のコメント、
  トップレベルのフラットな `key: value`、文字列/整数のスカラー、文字列のリスト（フロー
  `[a, b]` とブロック `- a` の両方）。アンカー・複数ドキュメント・ネストしたマップ・複数行
  文字列など、本格的な YAML の機能は**意図的に非対応**。この設定ファイル以外の用途には使わない。
  対応形が固定・既知（自分たちが書く 1 ファイルだけ）だからこそ許容できる割り切りであり、
  任意の YAML を受け取る汎用パーサとしては使えない。
- `dlp.config.json`（旧設定、`_comment` ハックを含む）は用済みになった。
- Python バージョン要件は変わらず「3.9 以降・標準ライブラリのみ」のまま維持できた。
