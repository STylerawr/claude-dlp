# 0001: Bash コマンドの解析を hook から外し、`permissions.deny` に委ねる

[← ADR一覧に戻る](List-Of-ADR_ja.md)

## ステータス

Accepted

## 背景

`dlp` hook は当初、`Read` / `Grep` だけでなく `Bash` で実行されるコマンド文字列
（`cat <保護対象>` のような読み取り）も自前で静的解析し、機密ファイルの内容が漏れないように
しようとしていた。

しかしシェルの意味論を静的に追い切ることは原理的にできない。検証を重ねるたびに新しい迂回路が
見つかった: 区切り文字の癒着、改行、`#` コメント、ANSI-C クォート、行継続、`bash -c` の多重
ネスト、`bash script.sh`、`eval`、バッククォート、ブレース展開、`$IFS`、`BASH_ENV` など。
実装は 2000 行を超えてなお塞ぎ切れず、ある迂回路を塞ぐ修正が別の穴や誤検知を生むことも
繰り返した。

## 決定

Bash コマンドの解析は hook から完全に取り除き、Claude Code 本体の `permissions.deny` に委ねる。

公式ドキュメントいわく、`permissions.deny` の `Bash(...)` ルールは「サブシェル・コマンド置換・
制御構文の本体を含め、どのサブコマンドが一致しても適用される」。`FOO=bar rm -rf tmp/` のような
先頭の環境変数代入も、`timeout` / `xargs` などのラッパーも本体側で剥がしてから照合される。
実測でも `cat <保護対象>`、`echo hi && cat <保護対象>`、`bash -c "cat <保護対象>"` がいずれも
ブロックされることを確認した。

hook 側は「内容ベースの判定とマスク版の提供」という、`permissions.deny` には作れない価値だけに
絞る。deny は**ファイル名の列挙ではなく命名規約パターン**で書き、hook の `always_target_globs`
（`*.pem` `*.key` `id_rsa` `credentials` `.env` `.netrc` `.pgpass`）と対になる
`Bash(*.pem*)` `Bash(*.env*)` `Bash(*id_rsa*)` … を settings.json に用意する。

## 結果

- **良い点**: 自前で追随するより本体のルールに委ねる方が確実で、保守量が桁違いに少ない。
  hook はスリムになり、Read/Grep の内容ベース判定という一点に集中できる。
- **トレードオフ**: `Bash` 経由の読み取りは hook では判定しない。`permissions.deny` はパス・
  ファイル名のパターン一致なので、変数や `$(...)` の出力でファイル名を動的に組み立てる形
  （例: `cat "$(echo <base64> | base64 -d)"`）は本体側でも文字列として一致しない。内容ベースの
  判定は Read/Grep 経路にしか無いという非対称性が残る。
- 規約外の名前を持つ秘密ファイルだけが穴として残る。その 1 個だけピンポイントで
  `Bash(*<名前>*)` を足すか、名前を規約に寄せるか、Bash `cat` は素通しと割り切る。
